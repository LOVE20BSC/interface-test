5 条失败逐条判定（全部是测试假设/夹具问题，产品行为不动；最后一节单独记一条新暴露的产品缺陷）：

1. **approvals 默认长期授权偏好（`e2e/approvals-numbers.spec.ts:287`）→ 修测试。**
   产品是对的：失败瞬间的页面快照里刷新后 checkbox 已是 `[checked]`，`approval-preference.ts` 的 `readPreference/writePreference` 读写同一把 `tokenApprovalUseUnlimitedByDefault` key。失败点在其助手 `selectTestToken()`：`page.reload()` → `connect()` 后立刻点开 `TokenPicker`，此时社区目录还没 settle；目录读回来后默认代币落地，`shared/ui/token-picker.tsx` 的「外部选中即关闭」effect 把刚打开的选择器关掉，选项随之消失。
   修法：打开选择器前先等 `approvals-balance` 出现「<symbol> 余额」（= 默认代币已选定且余额已读），再点触发器。

2. **batch 用例 M 余额读失败（`e2e/batch-transfer-numbers.spec.ts:515`）→ 修测试夹具。**
   产品回执逻辑是对的（`batch-audit.ts#summarizeBatchAudit` → `unverified`）。真正的失败原因是读注入根本没命中：页面的读全部经 viem client 的 **multicall 批处理**发出（wagmi `createConfig` 的 `batch` 默认 `{ multicall: true }`，`app/providers/wagmi.ts` 里 `http(...{ batch: { batchSize, wait } })` 只是 JSON-RPC 打包），`eth_call` 的 data 是 Multicall3 `aggregate3`（`0x82ad56cb`），`nativeBalances(0x93bdc1ab)` 只出现在它内层 `callData`。旧助手按 JSON-RPC 层把整条 `eth_call` 改写为 error，选择器永远匹配不到（实测 handler `matched=0`），既不会出现行内「—」也不会出现重试。
   修法：解析 `aggregate3` 入参定位目标子调用，把**响应里对应项**改成 `success=false`（其余子调用保持成功，避免连坐目录/发送方余额），并把端点匹配改成兼容 viem 规范化尾斜杠的正则；没有 multicall 包装的单条 `eth_call`（回执的 imperative read）仍整条改 error。用例 N（额度读失败）共用该助手，一并自愈。

3. **liquidity 边界（`e2e/liquidity-numbers.spec.ts:475`）→ 修测试。**
   产品是 QA D2 要求的双处渲染：设置弹层内与页面滑点区块同时显示同一条错误（关掉弹层后错误仍在页面上）。测试用 `getByText` 严格模式同时命中两处。修法：弹层内断言限定 `getByRole('dialog').getByText(...)`；关掉弹层后仍用 `liquidity-slippage-error` testid 断言页面那一条，断言强度不降。

4. **swap 慢钱包首笔（`e2e/swap-slow-wallet.spec.ts:210`）→ 修测试。**
   产品是对的：首笔 `pinnedNonce` = 链上 nonce、`usedNonce` = null（证明首笔已 pin nonce），全程只发 1 笔。失败来自「等 5 s 仍不出现恢复卡」与套件构建的短截止冲突：`scripts/e2e-chain.mjs` 把 `VITE_TX_DEADLINE_MS` 烘成 4000，5 s 时合法的 `slow` 卡（「这笔交易还没有被确认」）必然出现（截图 `swap-slow-wallet-pending.png` 即此状态）；断言「一张卡都不许有」实际是在测 e2e 构建的截止值，不是测修复。
   修法：允许 `slow` 卡，但断言**绝不是** nonceGap「这笔交易还卡在钱包里」、也不是 replaced；期间 `writesSent` 恒为 1（无需重新提交），最终回执哈希 = 首笔哈希、WETH +0.02。生产 90 s 截止下这段窗口仍是「确认中」。

5. **transfer-recovery D1（`e2e/transfer-recovery.spec.ts:295`）→ 修测试。**
   产品既有缩写约定是 `shared/lib/format.ts#shortenAddress(address, front=4, back=4)`：前缀 = `0x` + front 位；`shared/ui/tx-watch-card.tsx:36` 用 `shortenAddress(hash, 10, 8)` ⇒ 实际渲染 12 个字符前缀（`0x` + 10 位），`claim-airdrop-panel.tsx:313` 同样是 `10, 8`。测试写成 `${hash.slice(0,10)}…${hash.slice(-8)}`（8 位十六进制，`0x81aeb930…`），是测试假设错。修法：两处断言改为 `${hash.slice(0,12)}…${hash.slice(-8)}`（刷新前后各一处），注释写明沿用产品约定；**没有为过测试改产品的缩写**。
